# WORKFLOW.md — UniGuide (Агрегатор университетов)

Проект Модуля 2 «AI-Native App Sprint». Выполнен в одиночку, с покрытием всех четырёх ролей
из ТЗ (Frontend, Backend, AI Engineer, QA/Workflow Master) — правила по каждой роли, которые
управляли соответствующей частью разработки, лежат в `ai-rules/*_zhadyra.md`.

## Как это было построено

Был использован Claude Code с ключом OpenAI API для чат-бота в рантайме.
Файлы `ai-rules` подписаны соответственно требованиям проекта.

**Последовательность:**

1. Развернула Next.js 16 (App Router, TypeScript, Tailwind) через `create-next-app` и перенесла
   результат в существующий git-репозиторий.
2. Проверила документацию Next.js 16 и Prisma через **Context7 MCP** до написания хендлеров
   роутов и схемы — обе библиотеки оказались новее обучающих данных ассистента, с реальными
   ломающими изменениями (требование driver adapter для SQLite в Prisma 7; асинхронные
   параметры роутов начиная с Next.js 15). В итоге осознанно закрепила Prisma на версии 6:
   документация показала, что путь SQLite в v7 требует driver adapter / `node:sqlite`, что
   добавляет сложность без выгоды для этого проекта.
3. Собрала схему Prisma и засеяла 20 реалистичных университетов из 12 стран вместе с
   требованиями к поступлению (экзамены, минимальные баллы, GPA).
4. Собрала слой запросов (`src/lib/universities.ts`), общий для публичных API-роутов и для
   инструментов ИИ — один источник истины, никаких отдельных или выдуманных данных для чат-бота.
5. Собрала публичные страницы (список + фильтры + детальная) как Server Components — проверила,
   что они работают, ни разу не открывая виджет ИИ-чата.
6. Собрала ИИ-слой: системный промпт, 4 инструмента, память сессии в БД со сжатием и самописный
   цикл вызова инструментов с ретраями с помощью TypeScript.
7. Написала модульные тесты (Vitest) и e2e-тесты (Playwright), затем через **Playwright MCP**
   вручную проверила фильтрацию и панель чата на запущенном dev-сервере.
8. Нашла и починила баг с клиентской интерактивностью во время ручной проверки, после чего
   перезапустила весь набор тестов.
9. Перед деплоем на Netlify устранила блокер с записью чата на serverless (см. «Открытые
   вопросы» ниже) и слила рабочую ветку в `main`.
10. После первого реального деплоя на `https://uniguide-aggregator.netlify.app` провела живую
    проверку задеплоенного сайта (не только локальных тестов) и обнаружила, что чат всё ещё падал
    с `SQLITE_READONLY` — фикс из шага 9 проверял `NETLIFY`/`VERCEL` в `process.env`, а эта
    переменная оказалась недоступна в рантайме функции Netlify (только на этапе сборки).
    Промежуточно исправлено переходом на `NODE_ENV === "production"`, что живой чат починило.
    Заодно прогнала скилл `code-review` по `src/lib/ai/*` и `src/lib/db.ts` (ранее заявленный в
    `ai_zhadyra.md`, но фактически не запускавшийся) — ревью нашло 7 замечаний, включая то, что
    `NODE_ENV === "production"` — тоже догадка, а не проверка факта (сломала бы самохостящийся
    деплой с настоящей персистентной БД). Финальная версия `src/lib/db.ts` не гадает вовсе:
    проверяет реальную записываемость файла (`fs.accessSync`). Остальные 6 замечаний тоже
    исправлены (см. Рефлексию п. 2). Заодно привела структуру `ai-rules/*.md` к заголовкам из
    шаблона ТЗ (`# Role`/`# System Rules`/`# MCP & Tools`/`# Subagents`/`# Output Contracts`).

## Рефлексия

**1. Где ИИ сэкономил больше всего времени?**
Развёртывание всего стека Next.js/Prisma/Tailwind, наполнение базы 20 реалистичными
университетами с релевантными для каждой страны требованиями к поступлению (ЕНТ для Казахстана,
A-Levels/UCAT для Великобритании, Abitur для Германии и т. д.) и написание самописного цикла
вызова инструментов с ретраями и памятью со сжатием на TypeScript — каждая из этих задач вручную
заняла бы часы; вместе они уместились в одну рабочую сессию. Чтение актуальной документации
Next.js 16 / Prisma 6–7 через Context7 MCP также избавило от медленного цикла проб и ошибок
против API, которые не совпадают ни со старыми туториалами, ни с обучающими данными.

**2. Где ИИ ошибся?**
За время разработки всплыло девять конкретных проблем (сага с определением serverless-окружения
считается одной, хотя заняла три попытки). Самая серьёзная обнаружилась только
на живом деплое — остальные при проверке документации, повторном чтении кода, запуске приложения
локально или через отдельный аудит-проход скилла `code-review`. Показательно, что все локальные
тесты (18 модульных + 6 e2e) проходили зелёным, пока чат на реальном Netlify-деплое падал на
первом же сообщении — локальные тесты и живая проверка после деплоя ловят разные классы багов.

- **Самая серьёзная: две подряд непроверенные догадки о рантайм-окружении хостинга.**
  Serverless-фикс для записи чата (`src/lib/db.ts`) должен был определять, когда БД нужно
  копировать в `/tmp`, — и обе первые попытки угадывали это по косвенным признакам вместо прямой
  проверки. Версия 1 смотрела на `process.env.NETLIFY`/`VERCEL`: выглядело правдоподобно и даже
  «подтверждалось» локальной симуляцией (`NETLIFY=true npx tsx ...`), но по документации Netlify
  эта переменная гарантированно доступна только на этапе **сборки**, не в рантайме самой функции
  — что и подтвердилось на практике: первое сообщение в чат на
  `https://uniguide-aggregator.netlify.app` падало с `SQLITE_READONLY`. Поймано только прямым
  `curl`-запросом к живому `/api/chat` после деплоя, ни один локальный тест и ни один прогон
  `npm run build` эту ветку кода даже не затрагивали. Версия 2 перешла на
  `NODE_ENV === "production"` — задокументированную гарантию именно Next.js, а не платформы, — и
  живой чат заработал. Но скилл `code-review`, запущенный следом, верно указал: это тоже догадка,
  просто более надёжная — на самохостящемся деплое с настоящей персистентной БД в проде эта
  проверка молча подменила бы рабочие данные на эфемерный `/tmp`. Версия 3 не гадает вовсе:
  синхронно проверяет реальную записываемость файла (`fs.accessSync(path, W_OK)`) на пути, на
  который указывает `DATABASE_URL`. Проверка версии 3 локально через `chmod 444` на файле БД
  (чтобы точно воспроизвести read-only бандл, а не снова довериться симуляции через переменную
  окружения) вскрыла четвёртый баг в той же функции: `fs.copyFileSync` на macOS сохраняет права
  доступа исходного файла (используется clone-on-write системный вызов), поэтому копия read-only
  файла в `/tmp` тоже получалась read-only — молча сводя на нет весь механизм. Исправлено явным
  `fs.chmodSync(writablePath, 0o600)` после копирования, вместо того чтобы полагаться на поведение
  копирования, не гарантированно одинаковое на разных платформах. Урок: правдоподобная догадка,
  которая «работает» на одной платформе, — это всё ещё догадка; и даже проверку реального условия
  нужно перепроверять против настоящего сценария отказа, а не только против той симуляции,
  которая поймала предыдущий баг.
- **Модель молча теряла собственный текст рассуждения.** `SYSTEM_PROMPT` прямо просит модель
  «кратко объяснять, что и зачем» перед вызовом инструмента, но `AgentMemory.addAssistantToolCalls`
  хардкодила `content: ""` при сохранении хода с `tool_calls` — реальный текст рассуждения модели
  отбрасывался и не попадал ни в историю для следующих ходов, ни в какой-либо UI. Не поймано ни
  одним тестом (ни один e2e-сценарий не проверял содержимое поля reasoning) — нашлось только
  скиллом `code-review`. Исправлено: `addAssistantToolCalls` теперь принимает и сохраняет
  настоящий `message.content`.
- Найдено скиллом `code-review`, не тестами: цикл агента (`agent.ts`) перечитывал всю историю
  диалога из БД на каждой итерации цикла вызова инструментов — до 6 лишних раундов чтения на один
  ход чата. Исправлено накоплением сообщений в памяти внутри цикла вместо повторных запросов.
- Найдено скиллом `code-review`: вызов OpenAI при сжатии памяти (`compactIfNeeded`) не был обёрнут
  ретраями, в отличие от основного цикла агента — временная ошибка API валила весь ход чата
  целиком из-за фоновой операции. Исправлено общим хелпером `withRetry` (вынесен в новый
  `src/lib/ai/retry.ts`, переиспользуется и основным циклом, и сжатием).
- Найдено скиллом `code-review`: `tuitionUsd ? ... : "n/a"` в трёх местах `tools.ts` считал
  стоимость обучения в $0 (бесплатный университет) отсутствующим значением из-за truthy-проверки,
  хотя рядом `rankingScore` корректно использовал `??`. С текущими сид-данными не проявлялось (ни
  один университет не имеет `tuitionUsd: 0`), но было бы реальным багом для будущих данных.
  Исправлено переходом на явную проверку типа.
- `create-next-app` подтянул Prisma 7, где поддержка SQLite требует driver adapter
  (`node:sqlite` / `@prisma/adapter-*`) — в первом черновике схемы предполагалось, что
  классическая связка `env("DATABASE_URL")` просто заработает. Поймано проверкой документации
  через Context7 **до** запуска миграции, а не после.
- Фильтр Prisma `mode: "insensitive"` (только Postgres/MongoDB) изначально использовался для
  фильтрации по стране и специальности; SQLite его не поддерживает. Поймано повторным разбором
  схемы, а не упавшим тестом — стоит отметить отдельно, потому что иначе в продакшн уехали бы
  молча сломанные фильтры.
- Playwright, работавший с dev-сервером по адресу `http://127.0.0.1:3100`, отдавал страницу,
  которая прекрасно выглядела и в `curl`, и на скриншоте, но не имела никакой клиентской
  интерактивности: cross-origin-защита dev-режима Next.js 16 молча отдавала 403 на чанки
  `_next/static` и на websocket HMR для этого origin. Найдено через
  `browser_console_messages` в Playwright MCP, а не разглядыванием кода — само исправление
  (`localhost` вместо `127.0.0.1`) из исходников не видно в принципе.
- Первая реализация сжатия обрезала память диалога по фиксированному числу сообщений, из-за
  чего сообщение ассистента с `tool_calls` могло быть отрезано от своих строк-результатов
  `tool`, если сжатие срабатывало посреди длинного диалога, — такая комбинация невалидна для
  OpenAI API. Поймано на втором чтении `memory.ts`, а не упавшим тестом (теста, который
  прогонял бы достаточно длинный диалог, не было). Исправлено переходом на сжатие по границам
  целых групп вызовов инструментов вместо сырого счётчика сообщений.

**3. Что заняло бы в 3 раза больше времени без ИИ?**
Ручное написание данных о поступлении для 20 университетов — реалистичных и корректных для
каждой страны; корректная с первого раза разводка связей Prisma (многие-ко-многим для
специальностей, один-к-одному для требований, таблицы памяти сессий и сообщений); и чтение
реальной актуальной документации Next.js 16 / Prisma 6–7 вместо догадок по более старым и
привычным версиям. Все три — та самая работа, которая механическая, когда знаешь форму
результата, но медленная, если делать её с нуля.

## Открытые вопросы

Не доделано и не восстанавливается из чтения кода позже:

- **Запись чата на serverless — исправлено и проверено вживую.** `AgentMemory`
  (`src/lib/ai/memory.ts`) создаёт строку `ChatSession` и строку `ChatMessage` на каждый ход
  диалога, то есть приложение *не* является read-only во время обработки запроса, а вложенный
  через `outputFileTracingIncludes` `dev.db` лежит на serverless-ФС, доступной только на чтение.
  `src/lib/db.ts` проверяет реальную записываемость файла `DATABASE_URL` (`fs.accessSync`, без
  догадок о хостинге — см. Рефлексию п. 2 про две отброшенные попытки) и, только если он
  read-only, копирует засеянную БД в `/tmp/dev.db` один раз на холодный старт, открывая
  Prisma-клиент через опцию `datasourceUrl` уже поверх этой копии — код запросов не меняется.
  Подтверждено живым `curl` к `https://uniguide-aggregator.netlify.app/api/chat` после
  фикса — `200 OK` с реальным tool-calling ответом. Оставшийся компромисс: `/tmp` эфемерен для
  каждого инстанса функции, так что история чата не переживает холодный старт и не шарится между
  параллельными инстансами — для учебного проекта это приемлемо; для устойчивой истории —
  перейти на Turso/Neon, повторив `npx prisma migrate deploy`.
- **Сжатие не покрыто тестами.** `MAX_BUFFER_MESSAGES` равен 16, а самый длинный e2e-диалог
  состоит из одного хода, поэтому `compactIfNeeded()` под тестами не вызывается ни разу —
  включая логику границ групп вызовов инструментов, которая была предметом бага №4 выше.
- **Уязвимость `deepmerge-ts`** в парсере конфигов CLI Prisma — только для разработки, не стоит
  отката на пре-релизную сборку. См. раздел README «Замечание по npm audit».

## Решения, которые стоит помнить

Выборы, которые не были багами, а потому нигде больше не зафиксированы:

- **Один общий слой запросов** (`src/lib/universities.ts`) и для REST-роутов, и для инструментов
  ИИ, вместо того чтобы агент ходил в Prisma напрямую. ТЗ требует инструментов, работающих на
  реальных данных; общий слой делает это структурно верным, а не декларацией — и именно поэтому
  смена базы данных позже будет изменением конфигурации, а не кода.
- **SQLite вместо Postgres.** Каталог — фиксированный контент, впекаемый в деплой: `npm run build`
  каждый раз выполняет `prisma migrate deploy && tsx prisma/seed.ts`. Чтобы склонировать и
  запустить проект, не нужен ни один внешний аккаунт, а для учебного проекта это важнее, чем
  масштабируемость записи.
- **httpOnly-cookie для идентификатора сессии, память в БД**, а не состояние диалога в
  `localStorage`. Транскрипт остаётся на сервере (клиент не может подделать историю и подсунуть
  её в промпт) и переживает холодные старты serverless между запросами.
- **Prisma закреплена на 6.** Путь SQLite в v7 требует driver adapter (`node:sqlite` /
  `@prisma/adapter-*`); это лишняя поверхность без выгоды на таком масштабе.
